## چطور کار می‌کند

```
            خواندن (بدون توکن)
بازدیدکننده ─────────────────────► data/store.json  ◄──── GitHub Pages
                                          ▲
                                          │ نوشتن (با توکن)
                        مدیر ──────────  │
                         │                │
                         │  رمز عبور      │
                         ▼                │
                  data/vault.json (رمزگذاری‌شده)
                  AES-256-GCM  ◄──── PBKDF2-SHA256
```

1. کل لیست در یک فایل JSON ساده (`data/store.json`) زندگی می‌کند.
2. سایت عمومی همان فایل را از `raw.githubusercontent.com` (و در صورت قطعی، از نسخه ذخیره‌شده) می‌خواند.
3. مدیر رمز عبور را وارد می‌کند؛ مرورگر با آن، توکن گیت‌هابِ رمزگذاری‌شده در `data/vault.json` را باز می‌کند.
4. تغییرات با همان توکن به‌صورت یک کامیت روی مخزن نوشته می‌شوند و GitHub Pages چند ثانیه بعد نسخه تازه را سرو می‌کند.

هیچ سروری نمی‌داند رمز شما چیست. هیچ دیتابیسی وجود ندارد که از کار بیفتد.

## شروع سریع

```bash
git clone https://github.com/pouriasafari117/Online_list.git
cd Online_list
npm start                 # پیش‌نمایش روی http://localhost:8080
```

برای انتشار روی GitHub Pages:

1. مخزن را روی حساب خود فورک کنید (یا همین مخزن را استفاده کنید).
2. در **Settings → Pages → Build and deployment** گزینه **GitHub Actions** را انتخاب کنید.
   (ورک‌فلو `Deploy to GitHub Pages` خودش سایت را می‌سازد و منتشر می‌کند.)
3. آدرس سایت شما: `https://<username>.github.io/Online_list/`
4. یک‌بار `data/site.json` را با نام مالک/مخزن خودتان به‌روز کنید — یا از صفحه راه‌اندازی، خودش نوشته می‌شود.

> **نکته:** اگر نمی‌خواهید از Actions استفاده کنید، در همان صفحه Pages گزینه
> *Deploy from a branch → main / root* را انتخاب کنید. این سایت هیچ مرحله Build ندارد.

## ۱. ساخت توکن گیت‌هاب

توکن باید **فقط** به مخزن فروشگاه دسترسی داشته باشد:

| گام | مقدار |
| --- | --- |
| [ساخت توکن Fine-grained](https://github.com/settings/personal-access-tokens/new) | Repository access → **Only select repositories** → مخزن فروشگاه |
| Permissions | **Contents: Read and write** (Metadata خودکار Read-only است) |
| Expiration | ۹۰ روز یا ۱ سال — تمدید بعدی ساده است |

> توکن کلاسیک با اسکوپ `repo` هم کار می‌کند، اما دسترسی آن وسیع‌تر است و توصیه نمی‌شود.

## ۲. سینک توکن با رمز

دو راه دارید؛ هر دو خروجی یکسان (`data/vault.json`) تولید می‌کنند.

### الف) صفحه راه‌اندازی در مرورگر (ساده‌ترین)

صفحه `/setup/` عمداً **روی GitHub Pages منتشر نمی‌شود** — چون می‌تواند `data/vault.json`
را بنویسد، باید فقط محلی باز شود:

```bash
npm start          # سپس http://localhost:8080/setup/
# یا بدون Node:
python3 -m http.server 8080
```

1. توکن را وارد کنید.
2. «بررسی اتصال و دسترسی» را بزنید تا مطمئن شوید توکن دسترسی نوشتن دارد.
3. یک **رمز عبور قوی** (حداقل ۱۰ کاراکتر) تعیین کنید.
4. «ساخت فایل امنیتی» → «نوشتن در مخزن گیت‌هاب».

همین! رمز شما از این پس کلید ورود مدیر است.

### ب) خط فرمان (توکن از مرورگر عبور نمی‌کند)

```bash
node tools/make-vault.mjs --owner YOUR_USER --repo Online_list --branch main
# توکن و رمز به‌صورت تعاملی و مخفی پرسیده می‌شوند
git add data/vault.json data/site.json
git commit -m "راه‌اندازی امنیتی Online List"
git push
```

یا با متغیر محیطی:

```bash
GH_TOKEN=github_pat_xxx OL_PASSWORD='یک-عبارت-طولانی' node tools/make-vault.mjs \
  --owner YOUR_USER --repo Online_list --force
```

## ۳. ورود مدیر و انتشار

روی سایت، دکمه **ورود مدیر** در هدر را بزنید و رمز را وارد کنید.

- **نوار مدیریت** پایین صفحه: وضعیت (همگام / منتشرنشده)، دکمه انتشار، افزودن، تنظیمات و قفل.
- **موجودی**: با `+` و `−` کنار هر دستگاه، موجودی را تغییر دهید. تغییرات در همان تب ذخیره می‌شود.
- **دستگاه جدید**: دکمه «افزودن» در نوار مدیریت یا آیکون `+` کنار هر دسته.
- **دسته‌بندی و مشخصات**: هر دسته عنوان‌های مشخصات خودش را دارد (مثلاً «حافظه»، «رم»، «رنگ» برای موبایل و «پردازنده»، «گرافیک» برای لپ‌تاپ).
- **انتشار**: تغییرات را با یک پیام کامیت روی مخزن بنویسید. تاریخچه در `meta.history` ثبت می‌شود و «آخرین به‌روزرسانی مدیر» در صفحه اصلی از همان خوانده می‌شود.
- **قفل**: توکن از حافظه پاک می‌شود. هر بار ورود، توکن تازه از `vault.json` رمزگشایی می‌شود.

میان‌بر: `Ctrl/⌘ + S` برای انتشار، `/` برای جستجو.

## راهنمای مدیر با تصویر

مسیر `/help/` یک دفترچهٔ کامل فارسی است: گرفتن توکن، ساخت رمز، ورود، نوار مدیریت،
استپر موجودی، انتشار، فرم دستگاه، دسته‌بندی و فیلدهای اختصاصی، تنظیمات، تغییر رمز،
پشتیبان‌گیری، بازنشانی، امنیت و رفع اشکال — همراه ۱۴ اسکرین‌شات واقعی از خودِ پنل.

- لینک «راهنمای مدیر» در فوتر سایت، در دیالوگ ورود و در منوی مدیریت.
- دکمهٔ «چاپ / PDF» برای گرفتن نسخهٔ کاغذی یا PDF (مناسب آموزش کارمند فروشگاه).
- تصاویر WebP و lazy-load هستند؛ کل صفحه زیر ۴۰۰ کیلوبایت است.

## بازنشانی همه داده‌ها

در **تنظیمات ← منطقه خطر ← بازنشانی همه داده‌های لیست**. برای شروعی تازه:

| حذف می‌شود | می‌ماند |
| --- | --- |
| همه دستگاه‌ها و دسته‌بندی‌ها (به‌همراه مشخصاتشان) | نام و اطلاعات تماس فروشگاه، تنظیمات نمایش، رمز/توکن، تاریخچه |

محافظ‌ها: نمایش تعداد دقیق، تیک پیش‌فرض «نسخه پشتیبان بگیر»، و تایپ عبارت `حذف همه`.
اجرا **بلافاصله منتشر می‌شود** (یک کامیت با پیام «بازنشانی لیست موجودی») و ردیف
`reset` در تاریخچه ثبت می‌گردد. اگر اشتباه شد: تنظیمات ← بازیابی از فایل، یا Revert همان کامیت در گیت‌هاب.

## امنیت؛ دقیقاً چه چیزی محافظت می‌شود

> صفحهٔ `/setup/` روی دامنهٔ عمومی **اجرا نمی‌شود** (فقط `localhost`)، از خروجی Pages حذف است
> (هم در گردش‌کار Actions و هم با `_config.yml`)، و `npm run verify` هر سه شرط را چک می‌کند.

| پرسش | پاسخ |
| --- | --- |
| آیا توکن در سایت دیده می‌شود؟ | نه. فقط نسخه رمزگذاری‌شده (`vault.json`) در مخزن است. |
| آیا می‌توان `.gitignore` را جای امن‌سازی توکن گذاشت؟ | **خیر.** فایل‌های مخزنِ عمومی همچنان عمومی‌اند؛ چیزی که در `.gitignore` باشد هم روی `main` منتشر می‌شود اگر قبلاً کامیت شده باشد. `.gitignore` فقط جلوی کامیت‌شدن فایل‌های محلی را می‌گیرد (مثل `local.secret.json`). امنیت واقعی از **رمزنگاری** می‌آید. |
| رمز چطور ذخیره می‌شود؟ | ذخیره نمی‌شود. رمز با PBKDF2-SHA256 (**۶۰۰٬۰۰۰ دور**) کلید می‌سازد و همان کلید توکن را رمزگشایی می‌کند (vaultهای قدیمی با ۳۰۰٬۰۰۰ دور هم باز می‌شوند و با تغییر رمز به‌روز می‌شوند). |
| رمز ضعیف پذیرفته می‌شود؟ | نه. حداقل ۱۰ کاراکتر، رد رمزهای رایج، و تخمینِ حملات آفلاین روی همان صفحه؛ رمزی که با یک کارت گرافیک زیر ۷ روز شکسته شود پذیرفته نمی‌شود. |
| اگر رمز اشتباه باشد؟ | AES-GCM خطا می‌دهد؛ پیام «رمز نادرست است» نمایش داده می‌شود. ۵ تلاش ناموفق → تأخیر تدریجی (تا ۵ دقیقه). |
| اگر توکن لو برود؟ | از GitHub آن را Revoke کنید و از صفحه راه‌اندازی توکن تازه بسازید. |
| اگر رمز را فراموش کردم؟ | با «ورود موقت با توکن» وارد شوید → تنظیمات → رمز و توکن → **بازنشانی کامل رمز** (فایل امنیتی حذف می‌شود) و بعد صفحه راه‌اندازی را با توکن و رمز تازه اجرا کنید. |
| «بازنشانی کامل رمز» چه چیزی را پاک می‌کند؟ | فقط `data/vault.json` را؛ یعنی رمز و توکن رمزگذاری‌شده. لیست کالاها، دسته‌ها، تنظیمات فروشگاه و تاریخچه دست نمی‌خورند. بعد از آن باید توکن تازه بگیرید و رمز تازه بگذارید. |
| آیا کسی می‌تواند سایت را هک کند؟ | سطح حمله = یک فایل JSON عمومی + یک فایل رمزگذاری‌شده. بدون توکن، `vault.json` به‌تنهایی بی‌ارزش است. |

**پیشنهادهای تکمیلی**

- توکن را همیشه با انقضا و محدود به یک مخزن بسازید.
- رمز را در جایی جدا از مخزن نگه دارید (مثلاً همان یادآور رمز را طوری بنویسید که فقط خودتان بفهمید).
- اگر رمز را با کسی به اشتراک گذاشتید، از «تنظیمات → رمز و توکن» رمز را عوض کنید.
- اگر شک دارید که توکن لو رفته، از همان برگه «بازنشانی کامل رمز» را بزنید، توکن قدیمی را در گیت‌هاب Revoke کنید و از صفحه راه‌اندازی توکن تازه بسازید.
- HTTPS را جدی بگیرید: Web Crypto فقط در محیط امن فعال است (GitHub Pages همیشه HTTPS است).

## توسعه محلی

```bash
npm start          # http://localhost:8080  (و /setup/ برای راه‌اندازی)
npm run verify     # بررسی JSON، سینتکس JS، ارجاع‌ها و عدم لو رفتن کلید
npm test           # آزمون واحد: مدل داده، اعداد فارسی، CSV، رمزنگاری، API
npm run check      # هر دو مورد بالا (همان چیزی که CI اجرا می‌کند)
npm run vault      # ساخت vault از خط فرمان
```

بدون مرحله build، بدون `node_modules`. کل سایت با HTML/CSS/JS خالص کار می‌کند و
فونت وزیرمتن + آیکون‌های Material Symbols داخل مخزن هستند (هیچ درخواست خارجی برای آیکون/فونت نداریم).

### انتشار روی GitHub Pages

گردش‌کار `.github/workflows/pages.yml` با هر push به `main` سایت را منتشر می‌کند. فقط یک
کار یک‌باره لازم است: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
(دسترسی مدیریت مخزن لازم است و با `GITHUB_TOKEN` قابل انجام نیست؛ اگر این گام انجام نشده
باشد، اجرای workflow با پیام روشن متوقف می‌شود و چیزی خراب نمی‌شود.)

**قبل از انتشار**، `data/site.json` را بررسی کنید:

```json
{
  "owner": "username",
  "repo": "Online_list",
  "branch": "main"
}
```

اگر سایت روی دامنه‌ی اختصاصی اجرا می‌شود، همین مقدار `owner/repo` را نگه دارید؛
سایت داده را از raw می‌خواند و از مسیر نسبی به‌عنوان جایگزین استفاده می‌کند.

<summary>چند فروشنده می‌توانند هم‌زمان ادیت کنند؟</summary>

همه با یک رمز وارد می‌شوند. چون هر انتشار یک کامیت است، تغییرات هم‌زمان با پیام
«تغییرات هم‌زمان ثبت شده است» جلوی بازنویسی ناخواسته را می‌گیرد. برای تیم‌های بزرگ‌تر،
بهتر است چند مخزن/چند رمز داشته باشید.
</details>

<details>
<summary>چطور از لیست پشتیبان بگیرم؟</summary>

از «تنظیمات → نسخه پشتیبان → دریافت نسخه پشتیبان». فایل JSON دقیقاً همان چیزی است که
در `data/store.json` می‌ماند و با «بازیابی از فایل» برمی‌گردد.
</details>

<details>
<summary>فونت و آیکون‌ها از کجا می‌آیند؟</summary>

[Vazirmatn](https://github.com/rastikerdar/vazirmatn) (SIL OFL) و
[Material Symbols](https://fonts.google.com/icons) (Apache-2.0)، هر دو داخل مخزن —
هیچ CDN و هیچ درخواست شخص ثالثی در زمان اجرا وجود ندارد.
</details>

<details>
<summary>آیا داده‌ها آفلاین هم دیده می‌شوند؟</summary>

بله. سرویس‌ورکر پوسته سایت و آخرین `store.json` را کش می‌کند؛ اگر اینترنت قطع شود،
همان نسخه نمایش داده می‌شود و وضعیت «آفلاین» در فوتر مشخص است.
</details>
